## 支持流式转发的架构

### 架构流程

```
┌─────────┐  HTTP(SSE)  ┌──────────┐  HTTP(SSE)  ┌──────────┐
│ CLI工具 │ ←─────────→ │ 后端服务 │ ←─────────→ │ 算法服务 │
│         │   流式转发   │ (FastAPI)│   流式响应   │(Text2SQL)│
└─────────┘             └──────────┘             └──────────┘
                              │
                              ↓ SQL
                        ┌──────────┐
                        │  SQLite  │
                        │ (chat)   │
                        └──────────┘
```

### 流式转发流程

```
1. CLI发送 POST /chat/sessions/{id}/message (question)
2. 后端查询历史 → SQLite
3. 后端组装请求 → POST /analyze (携带历史)
4. 后端接收SSE流式事件
5. 后端转发每个事件给CLI (Server-Sent Events)
6. 后端保存消息到SQLite
7. 流结束，返回complete事件
```

### 关键技术点

**后端服务 (FastAPI)**:
- 接收CLI的SSE请求
- 转发算法服务的SSE流
- 使用 `StreamingResponse` 返回给CLI
- 异步处理，不阻塞

**CLI工具**:
- 发送SSE请求到后端
- 接收并渲染流式事件
- 保持连接直到流结束

### API设计

```python
# 后端路由
@router.post("/sessions/{session_id}/message")
async def send_message(
    session_id: int,
    request: MessageRequest
) -> StreamingResponse:
    # 1. 查询历史
    history = storage.get_history(session_id)
    
    # 2. 转发到算法服务
    async def event_generator():
        async for event in algorithm_client.analyze(
            query=request.question,
            chat_history=history
        ):
            # 转发事件
            yield f"data: {json.dumps(event)}\n\n"
            
            # 保存到数据库
            if event['type'] == 'complete':
                storage.save_message(session_id, ...)
    
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream"
    )
```

### 文件清单

**后端服务**:
1. `app/chat_service/__init__.py`
2. `app/chat_service/models.py`
3. `app/chat_service/storage.py` - SQLite存储
4. `app/chat_service/algorithm_client.py` - 算法服务客户端
5. `app/chat_service/service.py` - 流式转发逻辑
6. `app/chat_service/router.py` - SSE路由
7. 更新 `app/main.py`

**CLI工具**:
1. `tools/cli/chat_client.py` - 后端服务客户端

### 优势

- CLI和后端都是SSE流式通信
- 用户体验：实时看到处理进度
- 后端统一管理会话和转发
- 算法服务保持无状态
